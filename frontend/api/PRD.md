# Product Requirements Document (PRD)

## 1. Executive Summary
Adaptive Agentic GraphRAG is an enterprise-grade retrieval-augmented generation framework designed to eliminate hallucinations in mission-critical and regulated enterprise environments (such as financial compliance, biomedical intelligence, and legal analysis). The system combines dynamic query complexity routing, temporal knowledge graph edge decay, extrinsic algorithmic verification gating via RAGAS, and a bounded LangGraph multi-agent state machine.

## 2. Problem Statement
Traditional retrieval-augmented generation (RAG) paradigms face fundamental limitations:
1. **Vector Bottlenecks:** Dense vector embeddings perform well for single-hop semantic lookups but fail drastically at multi-hop relational pathfinding and structural entity reasoning.
2. **Graph Computational Overhead:** Indiscriminately querying a knowledge graph for simple, direct factual queries introduces high latency, Cypher execution bottlenecks, and expensive entity disambiguation.
3. **The Self-Correction Paradox:** Relying on the same generator LLM to critique and verify its own output leads to confirmation bias and unflagged hallucinations. Programmatic, extrinsic scoring is required.
4. **Knowledge Stagnation & Temporal Drift:** Static knowledge bases present stale or conflicting historical relationships without temporal recency weighting.

## 3. Core Functional Requirements

### 3.1 Dynamic Policy Routing
The system shall calculate query complexity $C(Q)$ dynamically using a logistic complexity model:
$$C(Q) = \sigma\left( w_c^T \cdot E(Q) + b_c \cdot \frac{E_Q \cdot \text{depth}_Q}{1 + \log(D_Q)} \right)$$
- **Single-hop ($C(Q) < 0.35$):** Routes strictly to Dense Vector Search (ChromaDB) to maintain sub-second latency SLAs.
- **Multi-hop ($C(Q) \ge 0.70$):** Routes to Knowledge Graph Traversal (Neo4j) to extract multi-edge entity pathways.
- **Hybrid ($0.35 \le C(Q) < 0.70$):** Executes both vector and graph queries, merging retrieved chunks and relational subgraphs using Reciprocal Rank Fusion (RRF).

### 3.2 Temporal Knowledge Graph Edge Pruning
To prevent stale relationships from contaminating generated answers, edge weights decay over time according to:
$$w(e, t) = w_0 \cdot \exp(-\lambda (t_0 - t_e))$$
- Relationships where $w(e, t) < \tau_{\text{decay}}$ (default $0.30$) are filtered out during Cypher traversal expansion.

### 3.3 Extrinsic Algorithmic Verification Gating
Responses generated by the synthesis agent must pass through an extrinsic verification gate computing:
$$S_{\text{total}} = \alpha \cdot S_{\text{faith}}(Y, K) + \beta \cdot S_{\text{ans\_rel}}(Y, Q) + \gamma \cdot S_{\text{temp}}(K)$$
- Default weights: $\alpha = 0.50$, $\beta = 0.30$, $\gamma = 0.20$.
- Gating threshold: $T_{\text{verify}} = 0.75$.
- If $S_{\text{total}} < T_{\text{verify}}$, the state transitions to a reflection cycle, refining the query and retrieval plan up to $N_{\text{retry}} = 3$.

### 3.4 Bounded State Machine Orchestration
- Orchestrated using LangGraph with typed state preservation.
- Strict termination bounded by $N_{\text{retry}} = 3$.
- Guaranteed deterministic fallback response on persistent verification failure.

### 3.5 Interactive Visual Interface
A Streamlit dashboard providing:
- Real-time modality badge indication (`Vector`, `Graph`, `Hybrid`).
- Debug views for Cypher query statements and vector similarity chunk ranks.
- Interactive GraphViz visualization of retrieved subgraphs.
- Metric breakdown charts ($S_{\text{faith}}, S_{\text{ans\_rel}}, S_{\text{temp}}, S_{\text{total}}$).
- Complete auditable JSON state trace logger.

## 4. Non-Functional Requirements
- **Performance & Latency:** Single-hop queries $\le 1.5$s; Hybrid/Multi-hop queries $\le 4.0$s.
- **Code Quality:** 100% type-annotated Python codebase; strictly $< 250$ LOC per file; zero hardcoded prompts.
- **Resilience:** Graceful in-memory fallback when Neo4j or ChromaDB instances are offline.
- **Security:** Parameterized Cypher execution to prevent Cypher injection vulnerabilities.
